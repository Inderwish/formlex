# FormLex 前端设计

将完整的设计输入落实到前端，权重决定表现强弱。已有页面默认追求布局、排版、配色和形状上的明显变化；用户明确的品牌、技术、业务功能与修改范围优先。

## 获取并保留完整输入

用户已经提供词条或网页生成的完整提示词时，直接使用整组内容及用户设置的权重，不重新抽取。只有用户明确允许取舍或重抽时才调整词条集合。用户要求多个方案时，每个方案都需落实整组要求，除非用户明确指定分组使用。

编排设计输入或转交其他 agent 时，仅保留任务、维度、词条名称与完整说明、有效权重及执行规则。省略词库来源、抽取模式、数量统计、记录信息和内部词条 ID；ID 只在查询、锁定或重抽等工具参数中使用。词条中的栏数、字号、色值和时长等设计信息照常保留。

没有现成词条时，需要 Node.js 22+，无需 npm install。以本 SKILL.md 的实际位置找到 `../../runtime/cli.mjs`，解析成绝对路径再调用。参数文件放在当前任务允许的临时目录，使用 UTF-8 并在结束后清理，不在插件安装目录写入文件。

1. `node "<插件根目录>/runtime/cli.mjs" libraries` 获取主题、维度与候选数量摘要，根据任务选择范围。
2. `node "<插件根目录>/runtime/cli.mjs" draw --input "<参数文件>"` 获取一组词条，以首次成功结果作为完整要求。默认原八维、协调模式、每维随机 2–3 条、色温随机、特色关闭。没有设置权重时全部按普通处理。
3. 需要解释概念或查询实现方向时，用 `search --input "<参数文件>"` 限量查询（通常 limit=8），不以新词替换原结果，不把完整 seed 词库读入上下文。

完整参数见 [CLI 参考](../../docs/cli.md)。特色按任务需要显式加入 dimensions 的 feature，独立 featureCount=1–5，默认 1。协调模式只排除显式互斥，不保证语义上的所有要求都兼容。

默认 builtin 离线运行且不保存历史。只有用户明确需要个人词库、编辑词条或历史同步时，添加 `--source workspace`，必要时用用户提供的本机 `--url`。连接失败不静默退回 builtin、不自行启动常驻服务；MCP 保持可选。抽取错误时保留已有输入和条件；historySaved=null 时先检查工作台历史，避免重复提交。

## 执行与交付

实现任务中用简短进度说明明确整组词条的应用分工，然后继续代码与验证。无需为正常的设计编排增加审批；遇到上述无法兼容的冲突时必须询问并等待相关决定。只要方案时到方案交付为止。提供可用的预览或文件链接，逐词检查结果，不用文字说明替代实际实现。
